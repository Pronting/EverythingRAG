## 2. 保留 / 排除清单（本报告首次产出，供核对）

依据 PRD 15.2 逐条落地口径。**「保留」= 迁移后仍是权威数据；「排除/转换」= 不保留为原形态，或必须经审阅后再生效。**

### 2.1 保留（不丢失）

| 类别 | 保留内容 | 依据 |
|---|---|---|
| 文件 | 字节内容 SHA-256 一致 + **mtime 保留**；上传资料复制进默认工作区目录并留旧→新路径映射；外部来源目录保留原地址 | PRD 15.2 第 5 步 / 15.3 |
| 向量 | 每个 block ID 的**维度与向量值一致**；全部历史 collection 身份、块 ID 保留；用 Chroma 公共 API 显式 embeddings 写入目标目录（避免 `embedder.dim` 触发远程调用） | PRD 15.2 第 6 步 |
| 图片 | 已完成识别内容与原图一致 | PRD 15.3 |
| 会话与消息 | 内容、顺序、归属、分支、归档与引用一致；迁移前已明确归属的数据保留原归属；原有文档/图片/会话引用补 `default` 来源 | PRD 15.2 第 7 步 / 15.3 |
| 记忆（可按规则转换的） | 旧 `active` 且通过来源与类别校验的条目 → 新 `active`；保留 ID、时间、原文、用户主动保存标识与替代关系；`source_message_index` 经消息映射转 `source_message_ids` | PRD 15.2 |
| 记忆状态 | 旧 `forgotten / superseded / orphaned` **保持状态** | PRD 15.2 |
| 索引 | 本地目录、术语基础索引、历史全文索引迁移后重建 | PRD 15.2 第 9 步 |

### 2.2 类别转换表（旧 → 新，实测与 PRD 15.2 表一致）

| 旧类别 | 新类别与条件 |
|---|---|
| `preference` / `constraint` | 明确的回答要求 → `response_preference`；具体方案条件 → `progress`（保留适用主题与范围） |
| `decision` / `conclusion` | 有用户确认依据 → `confirmed_conclusion`；只有讨论依据 → `progress`（明确保存讨论状态） |
| `identity` | 与工作区主题/项目有关 → `topic`；其他身份内容 → **迁移审阅记录** |

对齐证据：`tests/test_migration_v120.py::test_memory_conversion_table_matches_prd_15_2`（按 PRD 15.2 表逐行断言）。

### 2.3 排除 / 需审阅后才生效（不静默带入）

| 项 | 处理 |
|---|---|
| 旧 `knowledge_only` 设置 | **排除**：保存于迁移记录，设置页移除该开关，运行不再读取该字段；用户在具体问题里提出的资料范围要求改由 Intent Agent 记录 + 工具范围检查执行（PRD 15.2 末段） |
| 无法确认来源的记忆条目 | 进入**迁移审阅记录**，由用户选择归属并确认内容后启用 |
| 引用无法核验的条目 | 进入审阅记录，**不能自动取得有效状态** |
| 旧 `pending` 条目 | 保留在审阅记录中，**用户确认前不进入快照** |
| 类别暂不能转换的条目 | 保留完整迁移记录 + 对应失效标记，**阻止自动提炼重新启用** |
| 需要模型才能生成的扩展目录信息 | 不作为迁移阻塞项：迁移完成后作为**独立任务**运行并显示状态 |
| 来源目录本身 | 保留原地址（不搬移外部目录） |

### 2.4 与架构 §6 D16 的关系（字段计数，不要混用）

D16 是**契约字段计数更正**（`RouteDecision` 12 / `ResearchTask` 9 / `Evidence` 12 / `memory.json` 条目级 11，实现按 PRD 全字段交付即**超集，不排除任何字段**）。本节的「保留/排除」是**迁移语义**上的保留与排除，两者不是同一件事：D16 说明「迁移后的结构中字段一个都不少」，§2.3 说明「哪些旧语义不直接继承」。

## 3. 数据一致性校验（PRD 15.3）逐项口径

| 检查 | 要求 | 本次口径 |
|---|---|---|
| 会话和消息 | 内容/顺序/归属/分支/归档/引用一致 | 迁移用例覆盖（`test_a26_missing_workspace_and_memory_states_follow_the_rules` 等）；本轮 T_verify 未逐字段重跑 |
| 文件 | 字节 SHA-256 一致、mtime 保留 | 用例断言；真实 3.1 GB 语料**未跑**（live） |
| 向量 | 每个 block ID 维度与值一致、collection 与记录数一致 | 用例断言「计数以 Chroma API 为准而非目录扫描」（`test_a26_collection_counts_come_from_the_api_not_directories`） |
| 图片 | 已完成识别内容与原图一致，未完成任务可继续 | 用例断言 + `resume_pending_image_tasks` 按区续跑（逐区只读 sqlite3 读工作区列表，单区失败不阻断） |
| 默认工作区 | 原全局知识可检索、可浏览、可引用 | 工作区隔离用例（A06）覆盖「按区检索/浏览/统计」 |
| 其他工作区 | 原会话保留、知识统计准确 | A06 + A08 覆盖 |
| 无修改同步 | 不新增 embedding 或识图调用 | 同步用例覆盖（`tests/test_sync.py`）；迁移用例断言零远程调用 |
| 迁移恢复 | 各阶段中断后恢复得到同样结果 | `test_a26_resumes_after_interruption` + `test_a26_is_idempotent_when_rerun` |

> 说明：上表除标注者外，均为**既有离线用例的通过状态**（本轮全量运行随 §4）；T_verify 本轮**未**在真实数据目录上重跑 15.3 的逐字段核对——那属 A26 live 范畴。

## 4. 已知随机失败（复现矩阵，已裁定不再投入）

| 运行方式 | 结果 |
|---|---|
| 单独运行 `tests/test_migration_v120.py` | 0 失败（多次；本轮单独运行亦通过） |
| 全量 `pytest -q` | 按裁定可能随机失败（约 1/4 概率）；**本轮全量（2026-09-20，t32）未复现（通过）** |

根因：Chroma HNSW 分段懒物化 + 跨 `PersistentClient` 实例的中间态（`Failed to get hnsw segment writer` / `Nothing found on disk`），属**库/环境层**而非功能缺陷。`backend/tests/conftest.py` 已加「每用例前后显式 `stop()` 存活 System 再清缓存」的尽力而为 teardown（不掩盖真实失败）。**按 (b) 记入报告，不再加固**（captain 裁定）。

> 口径提醒：`APP_DB_SCHEMA_VERSION` 现为 **3**（`agent_tasks` 复合主键），与 `storage.json` 的 `storage_schema_version`（`WORKSPACE_LAYOUT_VERSION`，当前 **2**）**不是同一个版本号，禁止互推**（架构 §6 D25/D37）。

## 5. A26（真实数据迁移）—— 未执行

- **状态**：**未执行**。
- **原因**：对象是用户真实 `~/.everything-rag/`（**3.1 GB：241 MB 向量库 + 22 MB 图片库 + 873 KB 会话历史**）。PRD 15.2 第 1 步要求「停止全部写入后备份」，且迁移失败可能影响用户正在使用的真实知识库。live 是否执行由用户拍板（`docs/tech/v1.2.0-open-decisions.md` D1），**开工前用户未表态**。
- **由谁在什么条件下执行**：用户在**备份完成后、方便回滚的时间窗**内执行（live-eval C 档）；迁移期间无写入进程；迁移本身要求 **远程模型调用数 = 0**（可用出网审计断言验证）。
- **已执行的替代证据（不冒充 A26）**：迁移的**离线**部分全部通过（幂等重跑、中断续跑、备份缺失/磁盘不足中止、零远程调用、集合计数以 API 为准、记忆类别转换表对齐 PRD 15.2）。真实 3.1 GB 语料的「保留向量/文件/图片/会话」实测值**未取得**。
