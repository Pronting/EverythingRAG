## 4. ⚠️ 真实数据目录污染陷阱（captain 亲历，已造成一次事故）

**任何探测/脚本只要 `import app.main`（或走 `TestClient(app)` 触发 lifespan），就会读真实 `settings.data_dir`（`~/.everything-rag/`）**：
- lifespan 会 `AppStore.open(app_db_path())` 建/开 `app.db`；
- 还会开向量库（`chroma.sqlite3` 及其 `-wal`/`-shm`），并调 `resume_pending_image_tasks()`。

**`tests/conftest.py` 的 monkeypatch 救不了这些路径** —— 它只作用于 pytest 进程内的 `settings` 对象；非 pytest 的独立脚本完全不受保护。

**captain 的实际事故（2026-09-19）**：`probe_app_boot.py` 的 docstring 自称「只读，不写用户数据」，但它在真实目录留下了 `app.db`（217,088 B，19 表全 0 行、无 `storage.json`，未迁移、零用户数据）并打开了 `chroma.sqlite3`。**根因是我的探针**，而不是 `tests/test_run_py.py`（后者其实**已经正确隔离**：它用 `subprocess` 拉起 `run.py` 时传了 `EVERYTHING_RAG_DATA_DIR=tmp_path`）。

**正确写法（必须在 import app 之前）**：
```python
import os, pathlib, tempfile
os.environ["EVERYTHING_RAG_DATA_DIR"] = tempfile.mkdtemp(prefix="erag-probe-")
# ↑ 必须在这一行之前完成，因为 config.Settings 在模块导入时实例化
sys.path.insert(0, ".../backend")
from app.main import app
```
**验证方法**：跑脚本前后对比 `~/.everything-rag/app.db` 的 mtime，**必须不变**。

⇒ **t11 的验收/评测脚本一律适用此规则**。任何脚本若需要真实数据，必须由用户显式同意并显式传入数据目录，不得依赖默认值。

**仓库级排查（`workspace-isolation` 只读 grep 复核，captain 采信）**：
- `EVERYTHING_RAG_DATA_DIR` 全仓**只出现 1 次** —— `tests/test_run_py.py:161`，且**用得正确**；
- 非 pytest 路径里 `app.main` 的唯一导入者是 **`scripts/run.py:220`**（`uvicorn.Config("app.main:app", ...)`，真实启动器，读真实目录是**应有行为**）；
- 其余 `from app.main import app` 全在 `tests/**`，受 conftest 保护；
⇒ **仓库内没有其它需要修的脚本**；风险面就是**临时探针/脚本**（`.tmp_probe/` 这类）。**待写的 `benchmark/**` 与 `scripts/eval_*.py`（t11）风险最高**：若要 boot 应用或读索引，同样必须在 import 前设 `EVERYTHING_RAG_DATA_DIR`。

## 5. 本机取长输出的正确姿势（captain 为此浪费 4 轮）

`Start-Process -RedirectStandardOutput` / `Select-Object -First N` / 管道给 `Out-Null` 会造成**假挂起**：
子进程早已退出，父进程却一直等管道，表现为 150–180 秒超时且**一个字符都看不到**。
captain 因此把两个**自己脚本里的**错误误读成「应用死锁」。

正确姿势：

```powershell
$job = Start-Job -ScriptBlock { param($wd) Set-Location $wd; & ".\backend\.venv\Scripts\python.exe" -u "<script>" *>&1 } -ArgumentList (Get-Location).Path
if (Wait-Job $job -Timeout 120) { Receive-Job $job } else { "TIMEOUT" }; Remove-Job $job -Force
```

更稳的姿势：**让脚本自己把结果写进 `.log` 文件**（同步落盘），即使进程卡住也能看到卡在哪一步。
captain 的两个验收探针（`.tmp_probe/v120_prd/checklist_t2.py`、`checklist_isolation.py`）都按此改造。

## 5. 元教训：探针报 FAIL 时先怀疑探针

captain 的隔离探针一度"报"两条失败，实际是**探针自己猜错了 API**：
`WorkspacePaths` 的字段是 `chroma_dir` / `documents_dir` / `memory_json`（不是 `chroma` / `documents` / `memory`），
且 `WorkspaceContextFactory(data_dir, workspace_store, *, app_store=...)` 的第一个位置参数就是 `data_dir`。

⇒ 规则：**探针/测试报失败时，先确认自己的假设与真实 API 一致，再把它当成实现缺陷上报。**
⇒ 另一条：**成员仍在写文件的窗口内跑测试，结果不可信**——captain 曾在 `migration.py` 写入过程中跑到一次失败，
单独复跑与整套复跑均通过，属读到半成品。
