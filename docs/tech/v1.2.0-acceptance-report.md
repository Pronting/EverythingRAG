### 7.3 遗留改进项（**非 PRD 缺口**，本轮不开任务）

1. **`GET /api/conversations/{id}` 不暴露 `context_epoch`** ⇒ 前端的乐观并发预期只能来自「**观测到的**值」（`RunDetail.context_epoch` 或移动响应），**首次移动只能发 `null`**（不做校验）。后端**确实接受** `expected_context_epoch`（PRD 13.2 只要求移动接口接受它），且前端行为安全（不省略、不编造、不会因过期值把用户永久卡在 409），故 captain 裁定**接受该实现**，把「会话详情增 `context_epoch`（让乐观并发第一次就生效）」记为**后续改进建议**。

### 7.4 L3（前端 E2E 的证明边界）—— **保留并强化**（**不得删除**）
