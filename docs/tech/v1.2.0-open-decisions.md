**冲突**：CLAUDE.md §11「API key 不落 config 明文（环境变量 / 内存掩码）」；PRD 亦要求日志与界面不泄露密钥。

**性质**：这是 **V1.1.0 既有行为**，不在 v1.2.0 PRD 范围内 —— 所以我**没有擅自扩围**。已记为 t23 的 finding。

**选项**：
- (a) **本次一并修**（改为环境变量优先 + config 只存掩码/引用），代价：动 `settings_store` 读写路径，可能影响迁移与既有配置相容性，需要一轮回归。
- (b) **不修，仅记录**（推荐默认）：按 finding 写进报告，另开后续任务。

## D3. `deepseek-recipe` 本地 token 计数是否另开任务

**背景**：PRD 9.3 要求「本地请求计数采用官方 `deepseek-recipe`」。但官方包**未发布到 PyPI**（`pip download deepseek-recipe` → No matching distribution）。因此 `count_prompt_tokens` 在资源缺失时抛 `TokenizerResourceError`，**不按字符数估算**（这个取舍是对的）。

**现状**：tokenizer 资源已固定 —— 官方 v41 `tokenizer.json`，6,367,247 B，SHA-256 `81f64d1248a68ce3663e07ab3ee48b851e5df0e32d27cb98e4c9a268151e8d99`（本机实测下载后计算，写入 `TOKENIZER_PINNED_SHA256`/`TOKENIZER_PINNED_SIZE`）。

**选项**：
- (a) **另开任务**：把 tokenizer 文件放进 `~/.everything-rag/models/` + 交代 `deepseek-recipe` 安装方式 → PRD 9.3「开箱即用本地计数」达成。
- (b) **不另开**：报告标注「能力已实现，资源需用户提供」；本机无该资源时计数接口抛明确错误而非估算。

## D5. `ingestion/scanner.py` 日志直接打印完整路径

**背景（实测）**：`app/ingestion/scanner.py:76`、`:123`、`:136`
```python
logger.debug("跳过文件 %s: %s", path, exc)   # :76/:123 完整路径 + OSError（消息可能含路径）
logger.debug("跳过不可读目录: %s", exc)       # :136 原始异常
```
**违反 PRD 12.5「日志不得含文件路径/文件名」**，且连类名都没脱敏（仓内既有约定是 `type(exc).__name__`，见 `vision.py:129`、`image_worker.py:102` 等 8 处）。缓解：均为 `debug` 级，默认 INFO 下不输出。

**选项**：
- (a) **本次修**：三行改为 `type(exc).__name__`（+ 可用文件名哈希代替路径）。小改动。
- (b) **不修，仅记录**：列为 finding。
