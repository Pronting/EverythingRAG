# 「Everything RAG」技术选型决策文档

> **版本**：v1.0 定稿 ｜ **日期**：2026-08-11 ｜ **状态**：待产品作者审阅
> **用途**：作为脚手架搭建与后续开发的**技术底稿**，锁定技术栈、边界与待验证项。
> **生成方式**：由 6 路并行 sub-agent（T1–T6）分别调研产出（`docs/tech/T*.md`），本文档由主协调者综合并**裁决跨域冲突**。

## 1. 技术选型总览（决策总表）

| 域 | 决策 | 一句话理由 | 来源 |
|---|---|---|---|
| **RAG 框架** | **自研轻量管线**（markdown-it-py 解析 + 自研切块/同步/去重） | 差异化核心（增量同步/对话去重/防漂移）框架均无原生能力；"只认 MD + OpenAI 兼容单接口"砍掉了框架 loader/provider 生态价值 | T1 |
| **语言 / 服务** | Python + FastAPI + asyncio | RAG 生态最全；打包诉求被本地 Web 形态化解 | T1/T6 |
| **前端** | **React 19 + Vite + TypeScript**，Hash 路由，无 CSS-in-JS | 组件化收益大；纯静态 `dist/` 由 FastAPI 托管；v1.0 可套 Tauri 复用 | T2 |
| **向量库** | **Chroma**（`PersistentClient`，单一 collection 含模型指纹 `chunks__bge-m3__v1`） | 进程内、按 ID upsert/delete、元数据过滤齐全；接口隔离，开源期可换 LanceDB | T1/T4 |
| **嵌入模型** | **bge-m3 本地，fastembed（ONNX，免 torch）**，int8 档 ~600MB，惰性加载 | 嵌入必配且全局唯一（同向量空间）；纯文本不出机的技术基础 | T1/T4 |
| **对话模型** | **OpenAI 兼容可插拔**（默认本地 Ollama/llama.cpp，可选云端） | 一条 Provider 代码覆盖本地/云端，切换只改配置 | T3/T6 |
| **识图模型** | **本地 VLM 默认**（Qwen2-VL / MiniCPM-V，OpenAI 兼容端点），云端显式可选 | 方案 B 入库一次性、无延迟敏感；保住"数据不出机"卖点 | T5 |
| **流式输出** | **`POST /api/chat`（SSE）**，前端 `fetch + ReadableStream + AbortController` 手写解析 | POST 无 URL 长度限制、可携带完整历史、原生取消；帧契约用 T3 方案 | T2+T3 裁决 |
| **状态存储** | SQLite（`aiosqlite`）：指纹表 / 去重键表 / 切块清单 / 会话 | 单文件、事务、零运维；Chroma 为检索执行体 | T1/T4 |
| **部署形态** | 本地 Web 服务，`127.0.0.1:随机端口`，静态前端托管；Windows 首发脚本 | 零安装、跨平台、迭代最快 | T6 |
| **隐私审计** | **唯一 `OutboundClient`**（httpx 自定义 Transport）收敛所有出网 + 网络审计面板 + 日志脱敏 | "零外发"是计算断言非装饰；出网只可能来自模型 provider | T5/T6 裁决 |
| **打包（开源交付）** | **Tauri v2 壳 + Python sidecar**（python-build-standalone / PyInstaller onedir） | 开源向 Windows/macOS 交付桌面客户端；MVP 不打包，但内核保持可打包 | T6 + 客户端决策 |
| **开源许可** | 产品 Apache-2.0；模型权重许可逐项审计（禁止捆绑非商用权重） | 宽松利于生态；模型权重与产品代码许可分离 | T5/T6 |

**架构骨架（T1）**：模块 `api / core / ingestion / models / vectorstore / retrieval / generation / util`；所有外部能力走 `typing.Protocol` 薄接口 + 工厂注册，出网只收敛在模型 provider 两个出口。

## 2. 六路技术域决策要点

### T1 — RAG 核心框架（`docs/tech/T1-RAG核心框架选型.md`）
- **自研管线**：解析归库（markdown-it-py 出 AST），切块器/编排/同步/去重全自研；不锁 `langchain*` / `llama-index*`。
- **切块**：标题为一级边界、段落为最小单元、代码块/整表不拆散、图片引用产独立描述块；**块 ID = `doc_id :: 锚点路径 # 序号`**（doc_id 基于归一化路径 hash，非内容 hash），直接用作 Chroma 文档 id。
- **对话处理**：通用结构特征识别 + 可插拔 `FormatAdapter`（置信度打分取最高），元数据含 platform/time/title/message_role/message_seq/dedup_key。
- **增量同步**：快路径 stat(mtime,size) 全扫毫秒级 + 慢路径 xxh64 内容比对；文件级指纹与对话去重键职责分离、双表维护；`last_seen` 过期判删；级联删除按 `where` 批量；局部修改按 chunk_id+content_hash 差分只重嵌变化块。
- **依赖最小集**：fastapi, uvicorn, sse-starlette(裁决后可不加), pydantic(-settings), markdown-it-py, fastembed, chromadb(关遥测), openai, xxhash, charset-normalizer, Pillow, aiosqlite。

### T2 — Dashboard 前端 UI（`docs/tech/T2-Dashboard前端UI.md`）
- **React 19 + Vite + TS**；Hash 路由（`#/chat` 等）；状态用 React 内置，不引入 Redux/Zustand。
- **5 视图**：问答（默认落地页）/ 导入 / 同步（差异预览）/ 设置（配置向导）/ 隐私（网络审计面板）。顶栏（品牌/同步状态/暗色/语言）+ 左导航。
- **流式渲染**：增量放独立 StreamingMessage 局部 state，100–150ms 节流 + markdown-it 渲染；掉帧则降级流式纯文本、完成后再渲染。
- **来源标注**：强制卡片列表，点击打开应用内 `SourceDrawer`（原文块+上下文+图片缩略图），走同源代理防路径穿越。
- **样式**：自研 CSS 变量设计令牌 + 语义化类，不用 CSS-in-JS（保严格 CSP）；暗色 `[data-theme]` 跟随系统；i18n 自研极简模块（zh 全量 + en 骨架）。
- **接口契约**：18+ REST 端点 + `POST /api/chat` SSE；统一错误体 `{error:{code,message,detail,request_id}}`。

### T3 — 流式输出 SSE（`docs/tech/T3-流式输出SSE.md`）
- **事件帧契约**：`meta`（来源卡片+低置信）/ `token`（增量）/ `done`（含 ttft_ms / tok_per_s）/ `error`（错误码）；状态码恒 200，错误走事件。
- **中文防乱码铁律**：帧内 `data` 永远是完整 Unicode 字符串（str→json.dumps→整帧），绝不按字节切；前端逐 token 用 `textContent` 追加，不实时重渲染 Markdown。
- **取消/中断**：「停止」= 断开连接 → FastAPI 取消生成器 → 关闭上游模型流；`request.is_disconnected()` 早停；中断后保留已流出内容 + 重试按钮。
- **断线/重连**：`retry: 3000` + `: hb` 心跳注释帧保活；**不做服务端续传**，重连=标记中断不自动续跑，避免半截内容重复插入。
- **指标**：进程内环形缓冲 + `done` 自带 TTFT/吐字速率；token 数优先取上游 usage；日志只记 request_id+耗时+错误码。

### T4 — 向量库与嵌入（`docs/tech/T4-向量库与嵌入.md`）
- **Chroma**：单一 collection（名称含模型指纹），余弦度量（`hnsw:space="cosine"`），个人规模 HNSW 默认参数；关匿名遥测。
- **元数据 schema**：source_type/source_file/platform/time/heading_path/anchor/chunk_type/image_path；本地文档 platform 写 `local` 而非空（Chroma 不支持 None）；「只看某平台」用 `where`，容忍过滤后 <K 条。
- **增量维护**：稳定 block_id 幂等 upsert/delete；**重建索引 = 新建 collection 重嵌→切指针→删旧**，旧索引全程可读。
- **嵌入**：fastembed 加载 bge-m3（1024 维，int8 ~600MB），应用级单例 + 惰性加载（冷启动 <5s）；8GB 机器 int8、4GB 机器切 gte-multilingual-base 兜底。
- **SQLite 协作**：指纹/去重/切块清单（含块文本）为增量决策中枢；**启动必经对账**双向修复（孤儿删、缺块补写）。

### T5 — 多模态识图管线（`docs/tech/T5-多模态识图管线.md`）
- **接入**：产品只当 OpenAI 兼容 HTTP 客户端，对接用户已装 Ollama/llama.cpp/LM Studio；默认 `Qwen2-VL-7B` Q4_K_M（~8GB 显存/16GB 统一内存），无独显退化 2B 或关闭图片；**产品零模型分发、不打包权重**，向导给 `ollama pull` 引导。
- **Provider**：底层共用 OpenAI 兼容 client，上层分 `VisionModel`（单图→描述）与 `ChatModel`（多轮流式）两个薄接口，本地/云端一条代码路径。
- **描述 Prompt 模板**：固定 7 段（画面主体/关键实体/OCR 原文/图表数据/关系结构/上下文关系/检索标签）+ 反幻觉约束，`temperature=0.2`。
- **入库**：Pillow 预处理（verify/exif_transpose/降采样 ≤1280px）→ 按降采样后内容哈希去重（同图只算一次）→ 文本先入库、识图后台异步补全 → 确定性 block_id 幂等 upsert；失败重试 2 次、单图失败不阻塞、失败率超阈值熔断。
- **隐私**：本地 provider 强校验 base_url 为 loopback，远程地址拒绝标记为本地；云端 opt-in 三要素 + 常驻警示条；出网仅"降采样后图片字节"，默认不携文件名/路径/上下文。

### T6 — 配置 / 隐私 / 部署（`docs/tech/T6-配置隐私部署.md`）
- **配置**：config.json + pydantic v2 + `schema_version` 迁移 + 原子写；三模型字段五件套 `provider/base_url/model/api_key_ref/api_key_hint`；key 三层来源 `env: → memory: → keyring:`，落盘零密钥。
- **换嵌入模型**：`embedding_identity` 指纹比对触发重建索引闸门，重建完成前阻塞检索/入库。
- **云端 consent 强制点**：后端 `cloud_consent` 标志未置即拒绝出网路由（409），纯 UI 确认不够。
- **网络审计**：出网收敛唯一 `OutboundClient`（httpx 自定义 Transport），CI 静态检查禁止 net/ 外裸用 requests/urllib；审计表记时间/域名/数据类型/数量/字节/结果，不记正文；模型下载也计入审计。
- **日志**：stdlib logging + `RedactingFormatter`；路径/文件名用非敏感 `file_id` 替代；API 错误不回显响应体/base64。
- **部署**：`run.py` + socket 先取随机端口 + 复用上次端口 + 自动开浏览器；Windows `install.ps1` + `start.bat`；**MVP 单前台进程、不做开机自启**。
- **打包**：短程 PyInstaller onedir → 中程 Tauri + python-build-standalone sidecar（最大风险点，需 spike）。

## 3. 跨子代理冲突点裁决

| # | 冲突 | 参与方 | 裁决 |
|---|---|---|---|
| 1 | **流式端点与前端消费** | T3：`GET /api/chat/stream?q=` + 原生 EventSource；T2：`POST /api/chat` + fetch+ReadableStream+AbortController | **采纳 T2 传输层**：`POST /api/chat`（SSE），前端 fetch+ReadableStream 手写解析（~80 行），天然获得 POST body 携带完整历史 + AbortController 取消。**采纳 T3 帧契约**：meta/token/done/error 事件 + 中文防乱码 + 断线不续传 + 指标埋点。GET+EventSource 降为备选（升级路径：后端字节流不变，前端换实现零影响） |
| 2 | **top-k 参数** | T1 指出 PRD 4.6 默认 k=5 vs 技术架构 K=20/取8 | **统一为 `candidate_k=20` + `context_top_k=5`**：检索召回 20，取前 5 入上下文；写入第 7 章功能需求/代码常量 |
| 3 | **Chroma 元数据限制** | T1、T4 | Chroma 元数据仅收 str/int/float/bool；`anchor_path`/None/图片清单等**非标量一律序列化进 state.db 双写**，Chroma 只存标量 |
| 4 | **出网收敛点** | T5：收敛 ChatModel/VisionModel 两出口；T6：唯一 OutboundClient | **采纳 T6 更强方案**：唯一 `OutboundClient`（httpx 自定义 Transport）为**唯一**出网实现，ChatModel/VisionModel 复用该 client；CI 静态检查禁止 net/ 外裸用 requests/urllib |
| 5 | **会话历史权威** | T2：前端持完整历史 POST 发送；T3：后端持会话、query 只传 q+conv | **采纳 T2**：前端持有完整历史随 POST 发送（后端无状态 in-flight）；后端 SQLite 持久化会话用于刷新恢复（`GET /api/sessions/latest`） |
| 6 | **本地目录 vs 拖拽** | T2 揭示的边界 | **浏览器读不到本地绝对路径**："选目录"= 后端枚举文件系统 `GET /api/fs/browse` 扫描就地引用（主路径，同步对象）；"拖拽"= 内容 POST 上传到受管目录 `~/.everything-rag/uploads/`（复制进受管空间）。两语义不可混，必须同步给后端 |

## 6. 开放问题（待实现时验证）

1. **模型精确版本/量化/许可**：Qwen2-VL / MiniCPM-V / bge-m3 的具体 tag、量化体积、许可文本（禁止捆绑非商用权重）——以官方文档为准，落地前审计。
2. **性能假设需实测**：本地识图吞吐（0.2–1 张/分钟）、bge-m3 int8 vs fp32 召回差异、流式 TTFT <3s / ≥20 tok/s、Chroma 100 万块内存峰值。
3. **Chroma 版本锁定**：跨大版本持久化格式不兼容，须锁版本。
4. **fastembed 不暴露 bge-m3 稀疏分支**：影响 v0.2 混合检索路径，记入决策点。
5. **打包 spike**：Tauri + python-build-standalone sidecar 是开源期最大风险点，需单独立项验证。
6. **模型下载助手的许可列表**：默认推荐/内置下载模型必须为宽松许可。

## 7. 桌面客户端交付（Windows/macOS 开源目标）

> 业务需求：开源后向用户提供**桌面客户端**（Windows / macOS），用户通过客户端完成配置与使用。本节确认交付形态与打包路线。

### 7.1 结论：现有技术栈符合需求，方向不换，补打包规划

| 层 | 是否符合 | 说明 |
|---|---|---|
| 前端 React + Vite | ✅ 符合 | Web 前端可**原样嵌入** Tauri/Electron 壳，复用 100% |
| 内核 本地 Web（FastAPI） | ✅ 符合 | 桌面客户端 = 「壳 + 内核进程」；本地 Web 服务即内核，MVP 浏览器访问、开源壳内嵌浏览器，内核不变 |
| Python 跨平台打包 | ⚠️ 最大风险 | chromadb / fastembed(onnxruntime) / uvloop 带 native 库，三平台各自打包是主要工程风险，需提前规划 |

### 7.2 打包路线：Tauri v2 壳 + Python sidecar

- **壳**：Tauri v2（Rust）——窗口 / 系统托盘 / 开机自启 / 自动更新 / 文件对话框 / 深链接；壳体积小（约几 MB）。
- **内核**：Python sidecar —— python-build-standalone（独立 Python 运行时）或 PyInstaller onedir 打包 FastAPI 后端；前端通过本地 HTTP/SSE 调用内核。
- 备选：Electron + Python sidecar（壳重 ~100MB+，不优先）；纯 JS 重写（牺牲 RAG 生态，不推荐）。

### 7.3 前置工程约束（MVP 阶段就要满足，避免开源时返工）

1. **进程分离**：UI 壳与后端进程分离，后端只暴露本地 HTTP/SSE，不绑定 UI 框架。
2. **动态端口**：后端随机端口 + 复用上次端口（scripts/run.py 已按此设计），不写死端口。
3. **数据目录可指定**：所有落盘（向量库 / state.db / 配置）相对 data_dir，客户端可定位到用户目录。
4. **无硬编码路径**：绝对路径只来自用户选择/配置，代码不写死任何机器路径。
5. **依赖可打包约束**：锁版本；chromadb 用嵌入式模式不带独立 server；native 库（onnxruntime/uvloop）三平台各打包一次并验证；规避不可打包的依赖。

### 7.4 跨平台 CI 与分发

- GitHub Actions **matrix（windows-latest / macos-latest / ubuntu-latest）** 从 v0.1 后期即跑打包冒烟（打包后启动后端 + `/api/status` 200），早暴露打包问题。
- 分发：Windows 代码签名 + macOS notarization（公证）；自动更新走 Tauri updater。
- 打包产物：安装包（`.exe` / `.dmg`）；**模型权重不打包**（用户本地拉取，见 T5 合规）。

### 7.5 边界

- MVP 阶段：以本地 Web（浏览器访问）为主，不做桌面壳，**但内核保持可打包**。
- 开源阶段：Tauri 客户端交付（Windows/macOS），Web 前端 100% 复用。
