# RAG 研究、引用与恢复

## 查询与文档范围

QueryPlanner 保留研究对象、来源描述和用户要求。多篇文档比较按各篇负责的问题生成查询。查询比较键统一空白、标点及大小写，保留词语顺序和关系方向。

`confirmed_document_scope` 根据实际知识目录确认完整标题或唯一书名片段，运行层将范围传入 `ResearchRequest`。工具层通过真实块元数据映射来源，在 `HybridRetriever` 执行检索前传入 `where`。无法解析范围内任何一个文档时，工具明确返回错误。普通目录候选仍作为研究线索。

同一轮的 `RunResearchState` 按工作区、知识版本、工具和参数共享实际结果。同一请求并发执行时等待首次调用；每次返回独立数据副本。缓存复用有独立标记，工具执行次数与复用次数保持区别。当前共享缓存位于进程内；已有工具记录和运行研究状态另由现有持久化机制保存。

## 原文与答案

命中简介或目录时继续读取相关正文。读取窗口保留文档名称、相交章节和实际字符位置，从中部开始或未读至末尾时注明局部读取。

通用解释等待研究任务完成，使用去重后的来源正文。连续追问可复用前轮有效知识引用，重新判断其与本轮问题的关系。

有来源的答案使用结构化正文项，每项关联来源标识及正文行范围。来源正文经过统一处理并编排行号，章节名称单独展示。程序按范围取得真实摘录，检查来源身份、边界、数值和公式变量；推导数值通过标准 `ast` 解析受支持的算式后复算。正文仍可使用 Markdown 标题、列表和表格。

核验失败时仅纠正对应正文项，保留通过检查的内容。纠正不能通过直接删除来源来绕过检查；无法获得依据时，正文与用户要求的缺口记录必须一致。审查资料保存完整正文项、选择范围与检查结果。

独立语义验收使用当前问题、用户历史、正文与真实来源，核对数值归属、成立条件、正文一致性和交付缺口。此前 assistant 的回答不构成新增用户要求。验收只返回具体问题和覆盖判断，局部纠正保留其他正文。程序检查与语义验收各有一次纠正机会，每次生成流程最多调用三次正文生成／纠正、两次语义验收；没有有效验收结果时保持可恢复失败。

这些检查提供引用一致性约束，不能保证模型对所有语义、示例和需求完整性的判断都正确，仍需真实用例核对。

## 联网与恢复

关闭思考时禁用联网，其余等级保持整轮共享额度。研究在需要时申请网络工具；批准、输入及可恢复失败期间的等待与执行时间分开记录。执行开始之前的批准等待不会重复扣减执行时间。网页参数范围判断结合参数所属正文，排除日期等无关数字。

批准请求进入等待状态后，驱动结束时检查持久化裁决；已裁决的请求继续执行，运行状态检查防止重复启动。失败和取消状态在对应结束事件发布前保存。

可恢复失败保留已有研究与计划。页面恢复时读取历史事件，随后从已有最大事件序号订阅新事件。收到结束事件后读取实际子任务状态，更新过程摘要。研究父任务取得所需证据后，其不再需要的未执行联网子任务明确取消并记录原因。

历史会话按每条用户消息的 `run_id` 恢复对应运行卡片，包括较早尚未取得正文的任务。恢复按钮绑定该卡片的运行编号。

模型流式调用分别限制首次增量／连续静默时间与总执行时间：前者为 120 秒，后者为 300 秒。正文和推理增量均刷新静默计时。同步桥另有限定排队时间，取消会传递给实际异步任务并关闭 HTTP 流。诊断仅记录时间、字符数量和结束类型。
