## 1. 用户问题与产品目标

用户在知识库中提出涉及原因、方法和工程建设的综合问题，希望获得能够支持回答的材料，并能从引用查看依据。当前系统能够找到正确文章，同时会把共享部分词语的无关分块送入生成模型并显示为来源。

本功能要求系统判断候选内容是否能够支持问题中的一个明确需求。最终结果可以包含多个互补分块，也可以为空。来源数量上限保持八个；实际数量由相关性、必要证据覆盖和内容预算共同决定。

### 1.1 问题类别

| 类别 ID | 类型 | 判断对象 | 典型情况 |
|---|---|---|---|
| C01 | 同词异义 | 相同词语在原问题和正文中的含义 | AI native 与客户端 Native 渲染 |
| C02 | 同领域、不同提问目标 | 正文是否提供问题所需信息 | 开发协作问题与 AI 告警面试记录 |
| C03 | 多主题分块 | 实际送入模型的整个片段 | 数据库问答与 Agent 问答共用一个分块 |
| C04 | 综合问题与局部证据 | 是否回答至少一个明确子问题 | 一段材料只解释人工审查负担，但对综合问题有帮助 |
| C05 | 近似内容中的资料不足 | 候选集有相似词语，但缺少所需信息 | 有产品介绍，缺少用户询问的内部配置或事故原因 |
| C06 | 补充内容引入无关材料 | 主分块与附加文字的完整输入 | 同标题邻近文字、图片说明被自动加入 |

### 1.2 产品成功条件

1. 原始 AI 提效问题返回支持其提问目标的证据，排除已确认的两个无关分块。
2. 同类问题的无关分块比例下降，短定义、数字、表格和局部证据继续可用。
3. 用户能够看到“正在筛选资料”、资料不足或准确的服务错误状态。
4. 被排除的分块不会出现在生成上下文、来源列表和引用编号中。
5. 每个被采用的证据都能追溯到评分文本、原始来源和配置版本。

## 3. 范围与关联项目

### 3.1 本功能交付范围

- 在现有知识库索引上增加查询阶段的相关性选择能力。
- 保留 dense、BM25、RRF 及查询变体的候选生成能力。
- 独立配置重排服务，校验完整响应，记录调用及候选决策。
- 建立可评分、可引用、可校验文本版本的 `EvidenceView`。
- 同标题补充、短文本解释、图片核对后的文字接受一致检查。
- 扩充真实问题评测，建立独立校准集和测试集。
- 同步设置 API、SSE、会话来源持久化及前端展示。

### 3.2 与 V1.2 的接口

本功能作为知识检索模块工作，可由当前 `ChatService` 调用，也可由 V1.2 的 `search_knowledge` 调用。V1.2 负责子问题规划、研究循环和跨来源答案核对；本模块接收完整检索问题，返回经过筛选的知识证据及明确状态。

请求必须带有调用方已经解析的 `RetrievalScope`。当前代码仍使用全局知识库时，显式标记 `scope_id=global`；工作区隔离完成后由调用方提供受限 collection 或 `where`。本功能不能把已有会话分组能力描述成知识隔离已经完成。

候选、邻近内容、图片说明、诊断和配置档案均继承同一个 scope。不得从其他 scope 补充材料。V1.2 的外呼授权由既有执行层完成，检索模块不得绕过授权。

索引文件、向量表示和现有 block ID 在本功能中复用。查询阶段的证据视图具有自己的版本，不修改原始笔记。短语索引、语料重新分块和生成式背景注入属于独立的索引需求，不能成为本功能通过验收的隐含前提。

## 5. 查询处理设计

### 5.1 处理顺序

1. 固定本轮原问题、scope、知识版本及设置快照。
2. 生成查询变体，运行 dense 与 BM25，使用 RRF 合并逻辑候选。
3. 构造证据视图及有明确来源关系的补充视图，形成有界候选列表。
4. 使用完整问题和视图文本调用 reranker，取得全部候选分数。
5. 校验响应完整性，根据档案的排除条件选出合格证据。
6. 若需要原图核对，只对合格图片执行现有核对能力；正文发生变化时更新视图并重新评分。
7. 在合格证据中去重、按分数排序、应用最多八个来源及内容预算。
8. 为最终集合分配 `S1...`；生成上下文与来源面板使用同一份文本。

评分期间不得生成正式答案。排序、预算选择、图片更新均不能加入未接受检查的新文本。

### 5.2 候选生成与数量

新增 `collect_candidates()`，复用现有查询、词法索引、去重、scope 过滤及 RRF 逻辑。其返回值包含逻辑候选和通道信号，不执行最终八个来源的选择。

新流程中的词法命中、dense 分数和当前词法补充判断作为诊断信号。关键词数量不能直接授权最终入选，原有语义阈值也不能在 reranker 前删除其可能恢复的正确候选。不存在、空正文、越界 scope、版本不一致的候选在输入校验时拒绝。

候选按 RRF 分数降序，同分按稳定 `candidate_id` 升序。重排候选上限由校准档案确定，搜索范围为 30、50、100；上限统计包括补充视图。评测必须报告截取前后的正确证据覆盖。

每个主候选最多产生一个补充视图。列表构造采用“每个主候选一项，再加入补充视图”的顺序，防止一个大章节挤占全部位置。最终仍按所用配置档案的固定规则排序和截取。

### 5.3 证据视图

`EvidenceView` 是评分和引用的最小对象。单个视图包含原始 block 或明确关联的一组原文片段。

| 字段 | 类型与含义 |
|---|---|
| `candidate_id` | 稳定 ID，由 scope、成员 ID、成员范围和视图版本生成 |
| `scope_id` / `index_revision` | 资料范围与本轮知识版本 |
| `primary_block_id` | 主要原始分块 |
| `member_refs` | 成员 block ID、字符范围、内容哈希、关联类型 |
| `display_name` / `heading_path` | 文件 basename 与标题；外呼不传本机绝对路径 |
| `evidence_text` | 实际进入答案上下文与来源面板的原文片段 |
| `ranking_text` | 固定模板组成的名称、标题和 `evidence_text` |
| `payload_hash` | `ranking_text` 与视图版本的 SHA-256 |
| `route_signals` | dense、BM25、RRF 的原始信号 |
| `view_kind` | `block`、`support_bundle`、`image_text` |

字符范围按 Python Unicode code point 的半开区间 `[start, end)` 记录，并用原文重新切片核验。视图不得通过改写、摘要或补写事实制造证据。显示包装文字与原文分开保存。

普通文字采用现有分块；多主题分块可根据现有 Markdown parser 输出的结构生成较小引用视图。解析使用 `markdown-it-py`，表格、代码和列表结构保持完整。问句与其回答不得因为空行被分离。结构无法确定时保留完整分块并记录类型，不能用猜测的主题边界修改内容。

### 5.4 补充内容规则

同标题仅说明存在结构关系，不能自动证明相关。一般补充片段作为独立候选接受评分。

对于短公式、字段表与紧邻解释这种必须联合阅读的内容，允许构造 `support_bundle`：同 scope、同来源、同精确标题、明确原文顺序，成员不超过三个，新增解释不超过 600 个字符；选择时保留完整的表格或代码结构，无法满足限制时不生成该组合。

组合使用完整文本评分，评测也按整个组合判断相关性。组合分数只表示组合整体相关，不能推断其中每句话都相关。C06 的人工标注与无关字符比例用于约束这一问题。

已选择组合与其成员单独视图重叠时，只保留信息覆盖完整且分数合格的一个版本。被排除的组合不得通过章节扩展、保留位置或补足结果重新进入。

### 5.5 图片文字变化

图片初始候选使用已存在的图片文字证据。现有原图核对能力由用户原有配置和授权控制，本功能不增加新的图像模型。

需要核对时，最多核对当前排序靠前的两个合格图片。核对结果替换相关视图并产生新的 `payload_hash`；同图的旧文字补充同步移除。对更新后的完整候选列表再执行一次重排和筛选，保持模型评分的候选集合口径一致。第二次筛选不得触发新一轮图片核对。对于当前问题要求原图核对的图片，只有本轮已完成核对的视图可以进入最终上下文；其余视图记录 `image_not_verified` 并排除，不能因为重新排序进入最终集合。

原图核对失败则本轮失败，禁止将未核对的旧文字标记为已核对。取消请求立即停止后续模型调用。评测需要同时覆盖纯文本路径和图片更新路径。

### 5.6 最终选择

仅保留 `rerank_score >= threshold` 的视图；分数同值依次按 RRF 分数、`candidate_id` 排序。去除重复或被组合完整包含的片段后，按照顺序加入，直到达到八个来源或 16,000 个正文字符的内容预算。

超过剩余预算的视图跳过，并继续检查后续合格视图，记录 `budget_exceeded`。不得从视图中间截取已评分文本。预算的 16,000 个字符是产品验收上限，生成请求仍要按所用模型 tokenizer 核对总上下文限制。

原有每标题配额不得使必要互补证据被低分分块替换。当前词法保留位置和章节补足不参与最终入选。返回值有 `selected`、`empty`、`failed`、`cancelled` 四类状态。

## 6. 模型服务与配置档案

### 6.1 选型和服务边界

本需求选择独立 HTTP 重排 Provider，使用现有 `httpx` 及 `outbound_client`。重点接入阿里云百炼 `qwen3-rerank` 的官方 HTTP 协议，接受独立 endpoint 与 API key。服务模型名与开源 `Qwen3-Reranker-4B` 分别标识，不能假定二者权重、长度限制和分数行为相同。

2026-09-19 官方文档给出的 `qwen3-rerank` 请求使用完整 endpoint `/compatible-api/v1/reranks`，顶层字段为 `model`、`query`、`documents`、`top_n`、`instruct`；响应的 `results` 位于顶层，每项含 `index`、`relevance_score`。正式服务地址由用户所在区域和业务空间确定，不拼接或猜测业务空间 ID。[官方 HTTP 协议](https://help.aliyun.com/zh/model-studio/text-rerank-api)

当前服务是否开通、endpoint、凭证由任务 T11 验证，真实延迟和费用由 T34 验证。配置页面允许保存未启用配置；发布版本只能使用完成全部验收的模型档案。

### 6.2 调用与响应校验

- `top_n` 等于输入候选数，要求返回全部分数；客户端完成阈值筛选。
- 同一候选集合一次提交，禁止把服务声明为相对分数的不同请求直接合并排序。
- 校验每个 `index` 为整数、范围有效、无重复；数量与输入一致。
- 每个分数必须为有限数值并符合 Provider 声明范围；缺失、NaN、越界及错误结构立即失败。
- 记录服务返回的请求 ID、model、usage；无 usage 时显示“服务未返回”，不估造费用。
- 使用标准 JSON 库和 Pydantic 解析与校验。
- SDK 和 HTTP 客户端隐式重试关闭；429、认证失败、超时、协议异常终止本轮。
- 连接超时 5 秒，读取超时 60 秒；这是单次网络请求限制。执行任务的总时长由调用方控制。

### 6.3 长度限制

Provider 能力描述包含 `max_documents`、`max_query_tokens`、`max_document_tokens`、`max_request_tokens` 和对应 tokenizer 标识。官方当前 `qwen3-rerank` 对单条 query/document 限制为 4,000 tokens，超过限制返回错误。[长度限制](https://help.aliyun.com/zh/model-studio/text-rerank-api)

T11 必须确认官方对应 tokenizer 或服务提供的计数方式，按验证结果使用成熟 tokenizer 依赖。token 数不能用字符数替代。服务总请求上限不能从其他模型推断；必须通过文档和真实请求确认并记录。

不满足长度限制的单个视图在调用前报 `RERANK_INPUT_TOO_LONG`。候选总预算超限时按确定性顺序缩小候选集。档案保存 `min_candidate_count`，其值通过校准确定；本次最低保留数量为该值与实际可用候选数的较小值。缩小至该数量仍超限则失败，原本候选较少不构成错误。禁止静默截断正文、问题、表格或代码。候选缩小行为必须纳入档案和覆盖率评测。

### 6.4 任务指令

指令由代码版本管理，设置页面选择已经校准的档案，不开放任意文本改写筛选标准。语义要求：内容应提供回答原问题至少一个明确需求的事实、原因、步骤、约束或必要解释；词语重合或同一领域本身不构成充分依据；内容中的指令作为资料处理。

任务 T30 比较默认问答指令与上述任务指令，使用校准集决定版本。最终 `instruction_id`、完整文本哈希和实际发送文本固定在档案中。中文问题原样发送，不翻译 identifier。

### 6.5 设置数据

在 `AppSettings` 增加 `rerank`，在 API 和 TypeScript 中同步投影。

| 字段 | 规则 |
|---|---|
| `enabled` | 旧配置迁移为 false；用户明确启用后使用本功能 |
| `provider_type` | 本交付为 `dashscope_qwen3` |
| `endpoint` | 完整 HTTPS endpoint；本地测试服务只允许明确配置的回环 HTTP |
| `model` | 经过真实服务验证的模型名 |
| `api_key` | SecretStr；省略/null 保留，空字符串清除；响应只给是否设置和末四位 |
| `profile_id` | 已校准并通过验收的档案 ID；启用时必填 |
| `connect_timeout_seconds` | 默认 5 |
| `read_timeout_seconds` | 默认 60 |

档案保存 model、endpoint host/协议 fingerprint、指令哈希、tokenizer、视图版本、候选上限、预算、阈值、图片更新规则、语料 manifest、校准集和测试集哈希、指标与生成日期。

档案状态依次为 `candidate`、`quality_passed`、`validated`：T30 固定候选参数，T32 完成质量验收，T36 核对全部验收证据后标记 `validated`。生产启用只接受 `validated`。隔离验收环境通过启动参数显式允许测试档案，绑定独立配置目录并在页面显示“验收环境”；该参数不能通过线上设置接口开启，相关测试也必须覆盖生产环境拒绝未验收档案的行为。

模型、指令、tokenizer、视图版本和评分协议变化时档案立即失配，启用请求返回校验错误。语料新增或修改后标记 `needs_validation`，继续使用当前兼容档案并明确记录新知识版本；“已验收”标记只对应档案验证过的语料版本。下一次发布需要在新语料上重新验收。

凭证变化会重建 Provider 客户端，但不改变模型相关性档案。密钥不得进入档案、日志或导出文件。没有配置时不能自动复用对话模型或嵌入模型的地址和密钥。

## 7. 相关性标注与校准

### 7.1 标注单位

人工审阅完整问题与最终证据视图，记录以下等级、可支持的需求 ID 和原文范围。

| 等级 | 标注意义 | 筛选目标 |
|---|---|---|
| 0 | 含义不同、对象错误或完全无关 | 排除 |
| 1 | 仅话题相近，未提供回答所需信息 | 排除 |
| 2 | 有效支持一个明确需求或必要解释 | 保留候选资格 |
| 3 | 直接提供关键结论、步骤、数值或必要证据 | 优先保留 |

分块不能因未被旧黄金集列出就自动标为无关。未标注项为 `unjudged`，参与最终结果时该次 Precision 评测无效，必须补充审阅。

### 7.2 真实数据集

新增至少 120 个独立真实语料问题，每类 C01–C06 至少 20 个；每类 10 个用于校准、10 个用于独立测试。问题必须有明确的信息需求，候选正文来自真实索引，禁止制造正文或模型分数。

同一原始问题的改写、同一关键证据族和复用的干扰分块族归入同一个数据分组，整组只进入一个集合。固定分组清单，独立测试集不用于选择模型、阈值、指令或候选数量。

对照方法的候选并集进行标注，至少覆盖所有可能进入最终上下文的视图、所有已知必要证据和高分干扰项。保存每条问题的 `required_targets`、允许的互补证据及明确 `forbidden_targets`。

AI 提效原始案例固定为发布回归案例。它用于确认已知故障解决，不计入独立测试集的泛化指标。私人正文、查询向量和服务原始响应保存在 Git 忽略目录；仓库保存数据集结构、脱敏 manifest 和统计。

### 7.3 校准方法

在校准集比较当前混合检索、仅增加重排、重排加筛选、完整视图筛选四个对照。保持语料、查询向量、生成模型和输入范围一致；真实服务响应允许本地记录后重放用于重复计算，但最终验收必须包含现场调用。

候选数量、指令和阈值一起选择。先要求校准集必要证据覆盖率不低于 95%，再最大化返回结果的宏平均相关比例，同等质量时选择耗时较低的配置。阈值候选来自实际观测分数，不预设 0.5 正确。

官方对服务分数的描述包含“当前请求内的相对分数”。因此档案固定候选构造方法，并验证候选顺序变化、加入真实干扰项和全无关候选集时的决定稳定性。若分数阈值无法同时满足覆盖率和误放行率，该 Provider/档案验收失败，不能发布为已解决。

相关性判断不代表内容真实性。笔记中自述的错误答案、历史版本和引用真实性仍由答案依据检查处理，不能用重排分数证明事实正确。

## 8. 用户体验、接口与错误

### 8.1 设置页面

设置增加“资料相关性筛选”：启停、服务地址、模型、密钥、连接测试、档案选择、档案验证日期与状态。说明外呼内容为本轮问题和候选片段。日常页面不展示 RRF、tokenizer 等实现参数。

保存与启用分别校验。`POST /api/settings/rerank/test` 使用固定公开文本检查真实服务连接、模型和响应结构，不读取私人知识库；连通成功不能显示为质量验收通过。未保存字段可以在请求体中提交测试，服务端不持久化测试密钥。

`GET/PUT /api/settings` 保持局部更新语义。启用但缺少凭证、endpoint 或有效档案时返回 422，旧设置保持不变。旧配置缺少 `rerank` 时读取为未启用，下一次合法保存写入该字段。

### 8.2 问答与 SSE

复用 `tool` 帧：`tool=rerank`，状态 `running`、`done`、`error`；前端显示“正在筛选资料”。重排执行不得阻塞 FastAPI 事件循环；使用异步 Provider 及受限并发，取消信号传递到 HTTP 请求。

新增可选 `meta.retrieval`：`status`、`profile_id`、`candidate_count`、`selected_count`、`trace_id`。`status` 为 `filtered`、`empty` 或 `disabled`。`failed` 和 `cancelled` 通过任务错误或取消事件结束，不发送带旧候选的成功 meta。

无有效知识证据时调用现有 `choose_answer_basis`：仅知识模式显示资料不足；允许通用回答时标记通用依据；用户已启用网页查询时可依据实际网页结果回答。零知识证据本身不触发额外联网。

### 8.3 来源与持久化

`Source` 增加可选字段 `relevance_checked`、`rerank_score`、`score_type`、`profile_id`、`evidence_hash`、`member_refs`。`similarity` 保持原始向量分数含义，不存入重排分数。

新结果展示“已筛选资料”，详细面板可显示“排序分数 0.812”，不得显示成正确率或概率百分比。未启用重排的来源保留匹配方式标签；旧记录缺少新字段时正常读取，其原始数值如展示则明确叫“向量相似度”。

来源面板展示实际采用的 `evidence_text`，并提供读取完整原文的既有入口；完整原文不自动加入本轮生成上下文。组合成员均可追溯。会话保存、重载、移动和导出保留可选新字段，旧历史内容不重新打分。

### 8.4 错误状态

| 错误码 | 行为与文案 |
|---|---|
| `RERANK_NOT_CONFIGURED` | 筛选服务尚未配置；终止本轮并指向设置 |
| `RERANK_PROFILE_MISMATCH` | 当前模型或设置与验证档案不匹配 |
| `RERANK_AUTH_FAILED` | 筛选服务认证失败 |
| `RERANK_RATE_LIMITED` | 筛选服务请求受限，请稍后重试 |
| `RERANK_TIMEOUT` | 筛选服务响应超时 |
| `RERANK_INPUT_TOO_LONG` | 待检查资料超过服务输入限制 |
| `RERANK_INVALID_RESPONSE` | 筛选服务返回的数据不完整或无效 |
| `EVIDENCE_VERSION_CHANGED` | 资料在本轮处理期间发生变化，请重新提问 |

错误在出现位置抛出类型明确的异常，仅 API/任务边界转换为用户事件并记录脱敏审计。禁止静默返回未筛选内容、换用其他模型、自动重试或把错误当作无相关资料。

## 9. 诊断、性能与范围约束

每轮记录 `trace_id`、scope 摘要、知识版本、档案、候选 ID 的哈希引用、通道排名、四种分数的独立字段、视图哈希、排除原因、服务调用数量、耗时、usage 和最终顺序。

生产日志不记录问题、正文、绝对路径、密钥或服务原始错误体。现有 block ID 含有标题信息，日志导出必须转换成不可逆 `block_ref`。完整内容对照只存在用户主动运行的本地诊断文件，默认位于 `.tmp_probe/`。

排除原因固定为 `below_threshold`、`duplicate`、`covered_by_bundle`、`outside_candidate_window`、`budget_exceeded`、`scope_mismatch`、`version_mismatch`。词法补充条件继续记录为候选阶段信号，不能覆盖最终决定。

普通文字问答一次重排；图片文字更新时最多两次。HTTP 同时执行上限为两个请求；取消等待中的任务不会继续外呼。模型客户端按完整运行时配置创建，切换配置不影响已经固定快照的请求。

纯文本路径的新增等待时间目标为 P50 ≤ 2 秒、P95 ≤ 5 秒，属于验收目标，尚无本机测量结果。性能报告使用至少 50 个真实问题、单请求和双请求并发各执行三轮，分别报告首次调用和后续调用。图片路径单独记录核对耗时，不计作重排模型耗时。

费用报告使用服务实际 usage 与验证当日官方单价，列出每百次查询费用。服务未返回计量或价格未确认时明确记为不可计算，不能填写零。

## 10. 验收标准

### 10.1 指标定义

- `CandidateCoverage`：进入评分集合的必要证据数 / 全部已标注必要证据数。
- `RequiredEvidenceRecall`：最终结果覆盖的必要证据数 / 全部必要证据数；等价证据按目标组计一次。
- `ReturnedPrecision`：等级 2 或 3 的返回视图数 / 返回视图总数。
- `HardNegativeAdmissionRate`：最终结果中等级 0 或 1 的指定难负例数 / 进入评分集合的指定难负例数。
- `EmptyFalseContextRate`：无证据问题中返回任何知识资料的问题数 / 无证据问题数。
- `IrrelevantCharacterRatio`：最终正文中人工标注无关原文字符数 / 最终正文字符总数，按唯一原文范围计数。

同时报告逐题、逐类和整体指标。Precision 的整体和逐类验收采用有返回结果的问题的逐题宏平均，同时报告按视图汇总的比例。空结果的 Precision 记为未定义并单独报告空结果率；有答案问题返回空集，其证据 Recall 为零。不得用大量空结果提高 Precision。某类别全部返回空集时，Precision 标记不适用，通过该类证据 Recall 或无答案误召回要求进行验收。所有测试结果必须完成标注，否则对应指标不具备发布资格。

### 10.2 发布要求

| 验收 ID | 必须满足的条件 |
|---|---|
| A01 | 原始案例的两个明确无关分块在上下文和来源中均不存在；已标注必要证据全部保留 |
| A02 | 旧基准 72 个正例和 10 个负例全部通过原有严格检查，包括两个当前失败案例 |
| A03 | 独立测试集整体 `ReturnedPrecision` ≥ 90%，每类 ≥ 85% |
| A04 | 独立测试集整体 `RequiredEvidenceRecall` ≥ 95%，每类 ≥ 90% |
| A05 | `HardNegativeAdmissionRate` ≤ 5%；C05 无证据问题误放行率为 0 |
| A06 | C03、C06 的无关字符比例比同语料基线降低至少 50%；基线为零的案例保持零 |
| A07 | 每个最终视图的评分哈希与发送文本一致；scope 越界、编号错配、已排除内容重新加入均为零 |
| A08 | 真实服务调用、配置保存、历史加载、错误和取消路径通过；没有成功状态掩盖服务失败 |
| A09 | 达到第 9 节性能目标并附完整 usage 报告 |
| A10 | 后端检查、前端构建和真实浏览器流程通过；未授权启用或变更原始知识库的情况为零 |

这些数字是产品目标，不是已测成绩。任一要求未满足，报告具体失败案例并继续处理，不能降低标准或把失败案例移出集合以通过验收。

### 10.3 测试方式

纯函数检查使用真实笔记片段、真实响应保存件和实际 Pydantic 校验；集成测试使用真实隔离 Chroma、真实服务和真实 SSE。响应结构异常通过真实响应文件副本的明确测试变体验证解析器；这些负面输入只测试错误处理，不参与质量成绩。

禁止 mock、伪造模型分数、伪造成功 HTTP 服务或用固定答案替代模型调用。网络拒绝、失效凭证、真实关闭的本地端口可用于错误路径；无法安全触发的服务状态保留为未验证，不标为通过。

执行质量测试前检查语料 SHA-256、collection、嵌入 fingerprint、schema、逻辑块数和 ANN 完整性。线上与离线调用相同的候选、证据视图和筛选服务，禁止评测专用放宽规则。

## 12. 发布与维护

交付物包括代码、设置迁移、已验收档案、真实测试报告、失败案例说明、使用文档及诊断命令。档案通过验收后，用户在设置中明确启用；旧会话保持原内容，新的查询使用筛选流程。

运行中服务失败立即报错。用户明确关闭本功能后可使用原有检索模式，meta 标记 `disabled`，不能继续显示“已筛选资料”。更换模型或指令需要重新生成并验收档案。

语料持续更新时，用固定回归案例和新增真实误召回案例重新验收。记录模型、语料与配置版本，使后续结果可以重复检查。
