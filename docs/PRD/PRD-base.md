## 1. 产品背景（框架）

- **痛点**：重度 AI 用户同时在多个平台（ChatGPT / Kimi / DeepSeek 等）提问，信息碎片散落在本地文档与各平台对话中。需要重复解释背景、重复搜索"我之前说过什么"，时间成本高。
- **市场现状**：各平台内建"记忆"功能但封闭、黑盒、不可被用户主动检索；已有工具（Khoj、AnythingLLM、Notion AI 等）只做文档 RAG，不做"跨平台 AI 对话记忆"。
- **为什么现在做**：AI 平台对话量爆发 + RAG 技术栈成熟 + 本地模型/嵌入能力可用。个人数据资产化成为真实需求。
- **已定方向**：不做 token 接入（平台无对话历史 API），走"导出导入 + Markdown 归一化"路线。

## 2. 产品定位（框架）

- **一句话定位**：一个把"本地文档 + 各 AI 平台对话记录"统一向量化、用自然语言问答检索的个人知识第二大脑。
- **核心价值**：省时省力——不用再向 AI 重复解释背景，不用再翻找"我之前说过什么"。
- **产品边界**：纯本地部署（数据不出本机）；知识库可主动检索、可回溯、带来源标注。
- **成功指标（待完善）**：导入耗时、问答准确率、增量同步成本、用户留存等。

## 3. 目标用户与场景（框架）

- **核心画像**：多平台重度 AI 用户 + 有本地文档的知识工作者（先服务产品作者本人这一类人）。
- **核心场景**：跨平台对话与文档的统一检索问答（"个人知识第二大脑"）。

## 4. 核心功能需求（框架）

### 4.1 数据接入
- **已定**：第三方工具导出各平台对话（PDF/MD）→ **归一化为 Markdown 纯文本输入**。
- 架构原则：产品不绑定任何具体工具，**只认 Markdown**；多来源的价值在**元数据**（来源平台/时间/对话 vs 文档）。
- 不做：token 接入、浏览器抓取（高风险）。

### 4.2 文档处理管线
- 文本：MD 解析 → 按**语义结构切块**（标题/段落，不用固定窗口）→ 嵌入。
- 图片（**方案 B**）：多模态识图模型 → **文字描述** → 描述作为文本嵌入进向量库；**原图路径存元数据**（用于展示）。
- 外链 URL：仅存元数据展示，**不抓取链接内容**（避免范围蔓延）。
- 管线流程：入库时只发生一次；问答时不调用识图模型。

### 4.3 向量化与向量库
- 文本与图片描述统一走**嵌入模型**；问答时用户问题同样走嵌入模型检索。
- 向量库、切块、检索策略（向量 → 混合 → 重排，渐进）。

### 4.4 增量同步
- **已定**：手动"同步"按钮 + 启动时自动检查；**不做实时文件监听**（MVP）。
- 机制：**指纹比对**——扫描所有已知文件，未变化跳过（毫秒级），变化才重新处理，删除则移除。
- **去重键 = 平台 + 对话内容（规范化），不是文件 hash**（防手动编辑后 hash 失效）。
- 硬约束：**局部修改只更新局部块**（语义切块，防边界漂移）。

### 4.5 问答 Dashboard
- 检索增强生成；**答案强制标注来源**（哪个文件/哪段对话/哪个平台）。
- 流式输出（待确认技术细节）。
- 展示增强（可选）：回答时把相关原图喂给多模态模型"看图作答"。

### 4.6 模型配置
- 三模型分工：**嵌入模型**（必配）、**对话模型**（必配）、**识图模型**（条件性配置——仅开启图片功能时才需要）。
- 配置体验：识图模型 = 功能开关，不开图片功能就不用配，保证"纯文本用户数据 100% 不出机"。

### 4.7 隐私与安全
- 纯本地；知识库文件与向量库不出本机。
- **待拍板**：识图模型本地 vs 云端（图片是否出网）——直接影响隐私文案。

## 5. 技术架构方向（框架）

### 5.1 多模态 RAG 调研结论（已联网验证）
- **方案 B 为检索主干**：图片→多模态识图→文字描述→文本嵌入。主流务实做法，图内容可被文字检索。
- L3 多模态嵌入（CLIP）与 ColPali 视觉文档检索真实存在但重，MVP 不用。
- 生成时喂图给多模态模型（GPT-4V 模式）是叠加增强，不替代 B。

### 5.2 模块划分（框架）
- 数据接入层 / 文档处理管线（切块+图片描述） / 向量化 / 向量库 / 检索层 / 问答生成 / Dashboard / 增量同步 / 模型配置管理 / 隐私安全。

### 5.3 技术选型方向（待 sub-agent 4 调研完善）
- 语言（Python / TypeScript 等）、向量库（本地优先）、流式输出方案、本地部署方式、开源许可、跨平台支持。

## 6. MVP 范围（v0.1 需求集）

1. 选择本地目录 → 扫描 MD → 切块 → 向量化
2. 导入器：第三方导出的对话 MD（识别对话边界，打来源/时间元数据）
3. 图片：多模态转文字描述进库；原图路径进元数据
4. 手动"同步"：指纹比对 → 增量更新（增/改/删）
5. Dashboard 问答：检索增强 + 流式输出 + 强制来源标注
6. 数据不出本机

**明确不做（YAGNI）**：PDF/结构化数据、实时文件监听、L3 图像向量（CLIP）、链接内容抓取、跨源融合排序、记忆摘要/用户画像、多设备同步。

## 7. 版本路线图（框架）

- v0.1 MVP：见第 6 节。
- v0.2：图片问答时喂图增强、混合检索+重排、更多文档类型。
- v1.0：记忆摘要/用户画像、跨源融合排序、更多平台导入器。
- 开源：打包形态（本地 Web / 桌面壳 / 插件）待定，社区可插拔适配器。

## 8. 验收与质量（框架）

- 分阶段验收点：导入正确性、检索命中率、增量同步一致性、隐私合规。
- 非功能：性能（导入/检索/流式）、安全、可用性、可靠性（详见 sub-agent 5）。

## 9. 风险与开放问题（框架）

- **待拍板**：① 识图模型本地 vs 云端（图片是否出网）② 对话边界/去重键规范 ③ Dashboard 形态（本地 Web/桌面壳/插件）。
- 风险：第三方导出工具供应链依赖、增量同步体验质量、隐私信任、数据质量（对话语料噪声、重复、时间衰减）。

## 10. 竞品对照（框架）

- Khoj / AnythingLLM / Quivr / RAGFlow（文档 RAG，不做跨平台对话记忆）；ChatGPT Memory / Claude 记忆（封闭黑盒）；personal.ai / Mem（云端）；Rewind / Recall（录屏）。
- 差异化：**跨平台 AI 对话记忆 + 本地优先 + 可主动检索 + 开源**。
