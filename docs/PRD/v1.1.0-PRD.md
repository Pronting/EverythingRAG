## 1. 执行摘要

### 1.1 一句话

v1.1.0 把 Everything RAG 从「可检索的问答」升级为「**有跨会话记忆的问答**」——
**且不破坏"答案永远带来源"这一信任分水岭**。

### 1.2 验收一句话

用户在 A 会话说过的偏好或结论，在 B 会话提问时能被检索到、被引用，
且**点开引用能看到它提炼自哪一轮对话**。

### 1.3 为什么是"记忆即证据"而不是"AI 记住你"

总纲第 5 章把「平台记忆黑盒、不可检索、不可导出」列为**竞品的罪名**。
如果 v1.1.0 用"静默注入 system prompt 的记忆"来实现跨会话记忆，
我们就在自己的产品里复刻了那条罪名。因此本版的唯一实现路线是：

> **记忆是来源层（source layer），不是注入层（injection layer）。**
> 它必须可检索、可引用、可回溯、可删除、可关闭。

## 2. 与总纲的冲突与裁决（**必读**）

### 2.1 冲突一：总纲明文禁止"主动记忆"

总纲第 5 章原文：

| 来源 | 原文 |
|---|---|
| 5.6 不做清单 | ❌ **不是"AI 助手本体"**——不做会话式闲聊、不做 Agent、不做自动执行任务 |
| 5.6 边界口诀 | 凡是涉及"**系统主动获取、主动推断、主动记忆**"的，都不做 |
| 5.6 | 不是全知 AI——**不做主动记忆**、不预测用户、不自动给出未检索到的答案 |
| 3.x 差异化 | 把 ChatGPT Memory / Claude 记忆的"黑盒记忆"作为竞品缺口来主张 |

**冲突**：v1.1.0 的"记忆提炼 + 跨会话记忆"字面上踩在"主动记忆"这条红线上。

**裁决**：**改红线，但不是删除它，而是把它精确化**。

- 原红线真正要禁止的是**黑盒被动记忆**：用户不知道系统记了什么、记错了无法纠正、
  无法删除、无法导出、无法主动检索。
- 本版做的是**白盒可核验记忆**：每条记忆是原子条目，带来源指针、置信度、
  可查看、可编辑、可删除、可关闭，且**只能通过检索生效**——不静默注入提示词。
- 因此第 5 章的红线改写为：

> ❌ 不做**黑盒记忆**：不静默注入、不可查看、不可删除、不可导出、不可关闭的记忆一律不做。
> ✅ 做**白盒记忆**：原子条目 + 源指针 + 置信度 + 可审阅可删改，且只经检索生效。

**推理链红线保留并加强**：系统仍然不"预测用户"、不"主动提醒"、不"自动给出未检索到的答案"。
记忆只在用户提问时经检索参与，不产生任何主动行为。

### 2.2 冲突二：README 承诺了 MCP / Skills / 用户自定义工具

`README.md` 第 7 行与「未来功能」小节承诺了 "MCP、Skills 支持"。

**冲突**：本版决策 D9 明确**不做**用户自定义工具，且出网全部收敛在 `OutboundClient`（D2 决策 Q2-A）。

**裁决**：**修正 README，把承诺降级为明确的"不做"**，理由必须写清：
`OutboundClient` 是全项目唯一的出网审计关卡（总纲第十一章隐私红线）。
允许第三方可执行代码面（MCP Server / 用户工具）意味着存在**绕过审计**的出网路径，
审计面板将不再可信——这比"少一个功能"严重得多。

### 2.3 冲突三：总纲禁用 LangChain / LlamaIndex

总纲技术栈表与 `Agent.md` 第 36 行均规定：**自研轻量管线，不引入 LangChain / LlamaIndex**。

**裁决**：**冲突不存在，本版与该约束完全一致**，并显式扩展为
「**不引入任何 agent / memory 框架**」（含 mem0、Letta/MemGPT）——理由见第 3 章 D10。

### 3.1 为什么否掉框架（回应"要不要引入 LongChain / 参照 DeepSeek Harness"）

**结论：不引入框架，但引入一套内部 harness 契约。**

- **mem0 / Letta(MemGPT) / Cognee 这类"agent 记忆"库：明确否。**
  它们的核心价值是「自动抽取 + **隐形注入**」，而 D5 选择的恰好是它的反面。
  引入即意味着推翻 D1/D5，记忆退回黑盒。
- **LangChain / LlamaIndex：明确否。**
  其记忆层会自行发起 LLM 调用，**绕过 `OutboundClient`**，与隐私红线不同构；
  且总纲 `Agent.md:36` 已把"不引入"写成硬约束。
- **自建 agent 内核（照抄 Claude Code / DSH 结构）：否。**
  DSH 的工具执行面需要任意文件/进程权限，与本项目"出网全部审计"的模型不同构。
- **要抄的不是代码，是四样契约**：

| 契约 | 本项目现状 | 本版要做的 |
|---|---|---|
| 不可变策略 + 版本号 | ✅ 已有 `POLICY_VERSION = "rag-policy-v3"` | 记忆措辞纳入策略但**不升版本**（见 §5.4） |
| 工具契约 + 权限门 | ⚠️ 有工具帧，但硬编码 | 本版不动（D9 已关门），v1.1.1 预留 |
| 帧契约 | ✅ 已有 `meta/token/reasoning/tool/done/error` | 扩 `source_type: "memory"` 与 `M{n}` 段位 |
| 可回放可观测 | ⚠️ 部分 | 记忆评测集接入 `--enforce`（§7.3） |

> **一句话**：用"有测试钉住的显式契约"替代"框架替你决定编排"。零新依赖。

## 4. 数据模型与契约

### 4.1 记忆条目（`MemoryEntry`）

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | str | UUID hex |
| `category` | enum | `preference` / `identity` / `decision` / `conclusion` / `constraint` |
| `statement` | str | 一句话原子陈述（第三人称），上限 200 字符 |
| `confidence` | float | 0.0–1.0，提炼器自评 |
| `source_conversation_id` | str | 源会话 ID（回溯用） |
| `source_message_index` | int | 源消息下标（-1 = 无） |
| `quote` | str | **逐字**摘自用户原话的摘录 |
| `status` | enum | 见 §4.2 |
| `superseded_by` | str \| None | 被哪条取代 |
| `user_pinned` | bool | 由 `/记住` 显式创建 |
| `created_at` / `updated_at` | str | UTC ISO |

### 4.2 状态机

| 状态 | 参与检索 | 含义 |
|---|---|---|
| `active` | ✅ | 正常 |
| `pending` | ❌ | 置信度低于阈值，待用户在记忆面板确认 |
| `superseded` | ❌ | 被更新的同类记忆取代（保留回溯链） |
| `forgotten` | ❌ | 用户主动 `/忘掉`（软删除，可撤销） |
| `orphaned` | ❌ | 源会话已被删除，依据不可核验 |

**优先级规则（硬约束）**：

1. `forgotten` 优先于一切：用户遗忘意图**不得**被后台提炼复活，也不被 `orphaned` 覆盖。
2. `superseded` 不覆盖 `user_pinned`：用户显式记住的内容不被自动冲突消解静默取代。
3. 检索侧**回表 SQL 二次过滤**，不信任向量索引的时效性（见 §5.2）。

### 4.3 存储与索引指纹

| 项 | 约定 |
|---|---|
| 条目存储 | `data_dir/memory.db`（SQLite，标准库 `sqlite3` + `check_same_thread=False` + `RLock`，沿用 `ingestion/state_store.py` 风格） |
| 向量存储 | 独立 Chroma collection：`memory__{embedder.fingerprint}__v{MEMORY_SCHEMA_VERSION}` |
| 结构版本 | `MEMORY_SCHEMA_VERSION = 1`（与 `INGESTION_SCHEMA_VERSION` **独立**） |
| 统一指纹 | `make_memory_fingerprint(embedding_fingerprint) = "{fp}::memory-v1"` |
| 块 ID | `mem-{entry_id}`（稳定 → 重复索引 upsert 幂等） |
| 去重键 | `sha256(category + "\x00" + 空白折叠+小写后的 statement)`，唯一索引 |

**刻意不在记忆 collection 写 `source_type`**：记忆不在 `chunks` collection 里，
也不该为它扩展文档元数据 schema（`BlockMetadata`）。它靠 collection 归属与
`chunk_type == "memory"` 识别。

### 4.4 SSE / API 契约变更

**`meta` 帧新增来源子类型**（前端 `src/types.ts` 必须同步）：

```jsonc
{
  "source_id": "M1",          // 独立段位，不占用 S/W 编号
  "block_id": "mem-<id>",
  "text": "<statement>",
  "source_type": "memory",
  "chunk_type": "memory",
  "match_type": "memory",
  "platform": "memory",
  "source_file": "preference", // 类别值；前端映射中文标签
  "anchor": "conv-1#4",        // 源指针
  "category": "preference",
  "confidence": 0.9,
  "source_ref": "conv-1#4",
  "quote": "<原话摘录>"
}
```

**两处引用正则必须同步扩展**（漏一处会导致 `[M1]` 被静默删除）：

| 文件 | 正则 |
|---|---|
| `backend/app/generation/prompt_policy.py` `_CITATION_TOKEN_RE` | `\[(?P<source_id>(?:S\|W\|M)\d+\|\d+)\]` |
| `frontend/src/components/MarkdownContent.tsx` | `/^\[((?:S\|W\|M)\d+\|\d+)\]/` |

**`AnswerBasis` 不新增枚举值**：记忆是"来源"不是"模式"。
命中记忆但无文档/联网时，依据仍是 `general` / `insufficient`——
防止把一条提炼记忆讲成"库里有依据"。

**记忆 API**：

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/memory` | 列表（`status` / `category` 过滤） |
| GET | `/api/memory/{id}` | 单条 + 源回溯 |
| PUT | `/api/memory/{id}` | 编辑陈述/类别/置信度（改后重新嵌入该条） |
| DELETE | `/api/memory/{id}` | **软删除**（转 `forgotten`） |
| POST | `/api/memory/extract` | 手动触发后台提炼（`202 + task_id`，沿用 `/api/import` 模式） |
| GET | `/api/memory/task/{id}` | 提炼进度 |

## 5. 核心设计要点

### 5.1 D6：为什么记忆必须**独立于**文档检索通路（本版最大风险）

**问题**：记忆条目是短的第一人称陈述（"用户偏好 SQLite 而非 Postgres"），
文档块是长正文。把两者放进**同一个候选池**，实际结果是二选一：

- 记忆几乎永不入选（长文本在 RRF 名次竞争中压倒短文本）；或
- 为让记忆入选而放宽阈值 → 文档召回精度下降 → **打坏实测的 Hit@5 = 96.97%**
  （README 已公布，门禁含"纯 dense 命中加罚""数值噪声加罚"两套调优）。

**做法**：

1. 文档通路：现有逻辑与阈值（`DEFAULT_MIN_SIMILARITY = 0.60`）**一字不改**。
2. 记忆通路：独立 collection + 独立阈值（`DEFAULT_MEMORY_MIN_SIMILARITY`，**必须单独校准**）
   + 独立配额（`DEFAULT_MEMORY_TOP_K = 3`，远小于文档 Top-K = 5）。
3. 融合方式：**配额合并 + 独立段位**，记忆不参与文档的 RRF 名次竞争。
4. 两条通路共享**同一组查询向量**（否则两个通路的"相关性"不可比）。
5. 记忆命中或不可用**一律静默降级**，不影响 `answer_basis` 判定。

> **验收要求**：开启记忆前后，文档通路的召回结果必须**逐条相同**（§7.3 断言项）。

### 5.2 为什么检索要回表 SQL

用户点"忘掉"后，向量索引可能尚未更新。`MemoryStore`（SQLite）是**唯一权威源**，
因此检索命中后必须按 ID 回表取权威条目、二次过滤状态。

同一条规则适用于索引写入：`MemoryIndexer.upsert_entries(entries, store=...)`
传入 `store` 时会**先按 ID 取权威状态**再判定是否索引，避免调用方持有过期快照
把已遗忘的记忆重新写回向量库。

### 5.3 提炼的两道门禁（防记忆污染）

**这是本版最大的质量风险**：若每轮"今天天气不错"都产出一条记忆，记忆库会被噪声淹没。

| 门禁 | 机制 | 作用 |
|---|---|---|
| **信息量下限门禁** | 确定性启发式（`has_memory_signal`） | **省一次模型调用**；漏记可接受，误判只是多花一次调用 |
| **置信度阈值** | 提炼器自评 `< min_confidence` → `pending`（**不参与检索**） | 真正的裁决；宁可漏记，不可记错 |

**提示词硬约束**（`memory/extractor.py` 系统提示）：

1. 只提取用户**明确表达**的内容，**绝不推断**未说出口的偏好、性格或意图。
2. `quote` 必须逐字摘自原话。
3. **大部分对话应当返回空数组**——闲聊、一次性提问、纯事实查询不提炼。
4. 助手的话仅在用户明确认可时才可作为 `conclusion`。
5. 对话正文作为**不可信数据**包在标签内（与问答通路同一注入防护约定）。

### 5.4 记忆措辞纳入策略但**不升** `POLICY_VERSION`

记忆素材以 `kind="memory"` 标签进入上下文，并附硬约束：
「记忆是**推断**而非原文，引用时不得表述为文档原文；与本地知识冲突时**以本地知识为准**。」

**不升版本的理由**：`POLICY_VERSION` 描述的是**核心不可变策略**（身份、grounding、
防注入、引用规则）。记忆的优先级措辞属于**运行时候选来源的说明**，
不改变核心规则；升版本会让全部历史消息的 `policy_version` 失去可比性。
该判断须在评审中确认（见 §9 待确认项）。

### 5.5 斜杠命令的路由语义（写死）

`/查看记忆`、`/忘掉 x` 是**确定性操作**，**不走语义检索**，直接调 §4.4 的 API
返回结构化结果。`/记住 <内容>` 直接落一条 `confidence = 1.0`、`user_pinned = true`、
`status = active` 的记忆。

> **设计收益**：把"记忆召回率"这个最难调的部分，用"一类必须 **100% 命中**的请求"换掉了。
> 命令层与记忆层**互为兜底**——这是本版最干净的一处设计。

## 6. 范围

### 6.1 必须做（Must）

- ✅ 记忆提炼（后台、异步、`OutboundClient` 审计）+ `min_confidence` 门禁
- ✅ 跨会话记忆检索（独立通路 + 配额融合 + 回表过滤）
- ✅ `meta.sources` 记忆源 + `[M1]` 引用链路（含两处正则）
- ✅ 记忆面板 UI：查看 / 编辑 / 删除 / 失效标记 / 源回溯
- ✅ 斜杠命令 `/记住` `/忘掉` `/查看记忆`
- ✅ 源会话删除 → 记忆 `orphaned` 级联
- ✅ 记忆评测集（跨会话一致性正例 + 负例）接入 `--enforce`
- ✅ 文档对齐（总纲第 5 章 / README / Agent.md）

### 6.2 明确不做（Must NOT）

| 不做项 | 理由 |
|---|---|
| ❌ 用户自定义工具 / 可执行插件 / MCP Server / Skills | D9：`OutboundClient` 完整性因此永远成立，审计面板永远是真的 |
| ❌ 任意第三方代码执行面 / 沙箱 | 同上 |
| ❌ `/总结` `/对比` `/提炼` `/时间线` 等任务模板 | 命令收敛到记忆三条（D8），避免与词法路由语义打架 |

## 7. 验收与质量

### 7.1 功能验收

- [ ] A 会话说过的偏好，在 B 会话提问时被检索到并引用
- [ ] `[M1]` 可点击 → 展示原会话片段 + 「提炼」标识 + 置信度 + 回溯入口
- [ ] 记忆与文档源在 UI 上**视觉可区分**（不得被误读为"文档白纸黑字写着"）
- [ ] 记忆面板可查看 / 编辑 / 删除；`/忘掉` 后不再被检索但记录保留
- [ ] 删除源会话 → 派生记忆转 `orphaned`，历史 `[M1]` 标注"依据不可核验"而非断链
- [ ] `/查看记忆` `/忘掉` 为确定性返回，不触发语义检索
- [ ] 低置信度候选进 `pending`，不出现在检索结果中

### 7.2 隐私验收

- [ ] 记忆提炼出网**必须**经 `OutboundClient`，`/api/audit` 可见
- [ ] 默认关闭：未显式开启时零提炼、零出网
- [ ] 日志不得含记忆正文、会话正文、文件路径、密钥
- [ ] 记忆数据全部在本机 `data_dir`

### 7.3 回归与评测（硬门禁）

| 断言 | 要求 |
|---|---|
| **文档召回零回归** | 开启记忆前后，文档通路召回结果**逐条相同**（核心防回归用例） |
| `[M1]` 不被清洗 | `OutputGuard` 白名单必须放行 `M` 段位 |
| 编造记忆引用被删 | 本轮无记忆命中时，模型编造的 `[M1]` 必须被删除 |
| 记忆通路失败降级 | 记忆检索抛异常时，问答照常完成且无 `error` 帧 |
| 记忆不改变 `answer_basis` | 只命中记忆时依据仍为 `general`/`insufficient` |
| 既有评测不下降 | `scripts/eval_rag_quality.py --enforce`（82 样例，Hit@5 = 96.97%） |
| **新增记忆评测** | `scripts/eval_memory_quality.py --enforce`：跨会话一致性正例 + **负例**（不该引用的记忆不得出现） |

## 10. 附录：v1.1.0 实现结构

```
backend/app/memory/
├── __init__.py         # 模块导出
├── models.py           # MemoryCategory / MemoryStatus / MemoryEntry
├── store.py            # MemoryStore：SQLite 持久化 + 软删除 + 状态流转
├── index_schema.py     # MEMORY_SCHEMA_VERSION + 指纹 + collection 名
├── indexer.py          # MemoryIndexer：写入/更新/移出记忆向量
├── retriever.py        # MemoryRetriever：独立阈值 + 回表 SQL 二次过滤
└── extractor.py        # 提炼器：信息量门禁 + JSON 容错解析 + 注入防护

backend/tests/
├── test_memory_store.py    # 存储层：去重/状态机/软删除/源失效/编辑
├── test_memory_index.py    # 索引与检索：幂等/独立阈值/配额/降级
└── test_chat_memory.py     # 问答契约：[M1] 白名单/帧契约/素材标注/降级
```

**关键不变式**（实现必须始终满足）：

1. `MemoryStore`（SQLite）是记忆的**唯一权威源**；向量库只是索引。
2. 任何非 `active` 状态的记忆**不得**出现在检索结果中。
3. `forgotten` 状态**不得**被任何自动流程改写。
4. 记忆通路故障**不得**影响文档问答的任何行为。
5. 记忆**不得**改变 `answer_basis` 的取值集合。
