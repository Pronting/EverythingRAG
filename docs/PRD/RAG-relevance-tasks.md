| 完成依据 | 文件或数据产物、运行命令、真实结果和验收记录齐全 |

## 1. 执行规则

1. 每张任务卡独立标记状态：`todo`、`in_progress`、`blocked`、`done`。只有全部验收条件满足时使用 `done`。
2. 执行前读取当前文件、相关用户要求和工作区变更。用户已经修改的内容作为当前基础，不恢复此前删除的内容。
3. 实施任务只修改卡片列出的职责；发现额外前置条件时，记录明确依赖及具体证据。
4. 所有数据测试使用真实语料。模型质量验证使用真实服务，不能用固定分数、mock Provider 或固定答案代替。
5. 纯函数验证使用真实材料和明确的边界输入；协议错误检查只验证解析器拒绝非法输入的行为，不能计入模型质量结果。
6. 单个任务的检查由执行者完成，不能以“请用户测试”作为完成依据。
7. 任务的依赖关系表达先后条件，不构成启动其他 Agent 的授权。
8. 本任务清单不授权发布、合并代码或启用新的外呼服务。用户已经授权的开发范围按会话要求执行；真实服务需要有效配置及相应使用授权。
9. 中间产物保存在被 Git 忽略的 `.tmp_probe/rag-relevance/`；私人正文、查询向量、服务响应不进入公开仓库。
10. 下文测试文件是拟新增路径。涉及既有文件时按职责增加检查，不覆盖其他开发中的修改。
