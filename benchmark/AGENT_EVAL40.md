# 40 题真实文档观察

`agent_eval40.py` 使用独立端口的生产 Run API 提问，并启动真实页面的 DOM 观察器。每个应用实例使用独立 SQLite、Chroma 和配置副本。模型、推理等级与权限沿用实例工作区设置。

题目文件使用 JSON 列表，每项包含 `id`、`question`、`category`、`source_refs`、`expected_points`、`forbidden_claims`、`conversation_group`、`order`。`source_refs` 保留原文路径、标题、章节、引用、行号及 `chunk_ids`，由负责评测的 Agent 对照真实来源审查。脚本完整保留题目记录，不通过关键词判断回答正确率。

```powershell
backend/.venv/Scripts/python.exe benchmark/agent_eval40.py --cases .tmp_probe/agent-eval40-20260930/questions.json --ids Q01 Q02 --port 10001 --output-dir .tmp_probe/agent-eval40-20260930/results-10001 --timeout 900
```

相同 `conversation_group` 必须交给同一个执行器，按照 `order` 顺序执行。该组复用真实 conversation，独立题分别创建 conversation。已有终态结果会跳过；未完成结果要求检查现存运行进程，防止重复提问。

每题 JSON 保存 Run、完整事件、最终回答、引用、模型阶段耗时、工具事件及实际推理设置。`progress.json` 每五秒更新，能够在运行中检查阶段与事件数量。页面观察文件保存处理过程、可见推理、回答、来源面板、刷新结果及页面错误。原文与页面观察记录包含私人语料，仅保存于 `.tmp_probe/` 忽略目录。

超出时间限制时取消该 Run，并记录 `harness_timeout`。等待批准、等待输入、失败与取消均保留原状态，不能计为成功。回答质量、引用支持程度、分块边界及资料不足行为由评测 Agent 根据记录审查。

## 逐题观察标准

- 答案：关键事实、数字单位、适用条件、比较对象、时间先后和资料未提供的边界。合理同义表达可以通过，存在引用标签不能单独证明正确。
- 引用：逐项定位实际引用内容与源文件，检查引用是否直接支持结论、是否混入其他对象，以及引用范围是否足够理解结论。
- 分块：核对标准依据所在块、相邻块和所属章节；检查表格行列关系、代码与解释、列表前提是否分离。没有检索到某段内容不能直接证明切分错误。
- 工具与过程：检查任务计划、查询主题、文档范围、重复请求、取得证据后的停止条件、失败恢复和最终状态。页面过程与真实事件需要一致。
- 上下文：同组跟进是否使用前题对象与限制，是否误用其他会话内容，是否重复获取已经取得的相同证据。
- 页面：运行过程中是否有可见状态、答案是否连续更新、来源详情能否打开、刷新后内容是否一致，是否出现浏览器或接口错误。DOM 检查不等同于视觉排版检查。
- 性能：记录总时间、模型阶段时间、工具时间、首次可见答案时间，区分并行评测负载和服务端错误，不通过降低测试要求隐藏失败。

每位观察代理按题号保存判定与证据。问题记录包含分类、严重程度、确定程度、复现题号、事件或代码位置、实际现象、期望行为、用户影响。确定缺陷、资料准备问题、模型服务故障、观察器错误和待核实疑点分别记录；相同原因合并，保留各受影响题号。
